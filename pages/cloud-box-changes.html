Current version: pressure through the realtime hub (2026-11-13)

Replaces the polling design described further down. You see a box in trouble from the sidebar without opening its workspace, and resizing asks to confirm.

1 · Box

host-service samples every 5 s with smoothing (enter/exit thresholds, 60 s before stepping down), ignores kills from before this boot, reports only on change plus a 5-min re-send while under pressure.

2 · API

POST /api/cloud-workspaces/:id/box-pressure, host-secret auth like agent-status. Forwards to the realtime worker; nothing is written to Postgres.

3 · OrgHub (Durable Object)

Keeps only boxes under pressure. Sends the whole set to each window that connects, then one change at a time. Drops a box that stops re-reporting after 15 min.

4 · Desktop

A store fed by the existing realtime socket. Sidebar dot on every cloud row, hover status and kill for any workspace, banner for the open one. Live bars ask the box only while the hover card is open.

What it looks like

Changed along the way

  • Resize dialog removed. Replaced by the submenu, and by the same list as a dropdown from the hover card and banner.
  • Polling narrowed. First version polled every cloud row and checked every row's connection, which could keep sleeping boxes awake. Now only the open workspace.
  • Resize call moved out of React Query's observer, so the toast completes after the menu closes.
  • Memory used excludes reclaimable page cache, the way Docker and kubectl report it.
