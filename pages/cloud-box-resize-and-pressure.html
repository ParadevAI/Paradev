Cloud boxes: resize from the sidebar, and show when a box is struggling

A proposal for how the desktop app lets people pick a bigger box for a cloud workspace, and how it tells them their box is out of CPU or memory before they decide Paradev is slow.

The short version

  1. Right-click a cloud workspace → Machine size. A submenu lists the sizes the plan offers, with the current one checked. Picking one changes it at once; a note in the submenu says a running box restarts.
  2. Quiet until it matters. A box that is fine shows nothing new. The hover card always shows the size and two small meters. A dot appears on the sidebar row only when pressure lasts.
  3. The fix sits next to the warning. Every warning has a "Resize" action that opens the same size list, with the next size up marked.
The backend for resize already exists: cloudWorkspace.setMachineSize, which the CLI uses (superset workspaces update --machine-size). 3386 is UI only. 3387 needs one new signal, read by host-service on the box.

1 · Resize from the right-click menu

A submenu in the context menu that already holds Rename, Copy and Archive. Only cloud workspaces you can manage get it.

2 · Show when the box is struggling

Three levels, each louder than the last. Most people never see anything past the first.

Level
When
What the user sees
Fine
Default.
Nothing new on the row. The hover card shows size and two live meters, so the answer to "is it the box?" is one hover away.
Under pressure
CPU or memory pressure stays above its threshold for 2 minutes (see signals below). Clears after 5 quiet minutes, so the dot doesn't flicker.
Amber dot on the cloud icon in the sidebar. Hover card says what is limited and offers Resize. No banner, no toast: a busy build is normal.
Something gave way
memguard killed a process to keep the box alive, or memory pressure hit the level where the box stops answering.
Red dot, plus a banner inside the workspace naming what stopped, with Resize to X. Dismissing it hides it until the next kill.

3 · What we measure

Checked on a real cloud box (this workspace, 4 vCPU · 8 GB) on 2026-11-13.

"Throttled" is the wrong word for CPU here. The box's cgroup has no CPU quota (cpu.max = max, nr_throttled = 0). It is limited by its vCPU count, so the kernel never reports throttling. What does work is pressure stall information (PSI): the share of time tasks spent waiting for CPU or memory. The cgroup exposes it, so no Vercel API is needed.

SignalSource on the boxAmber whenRed when
CPU pressure/sys/fs/cgroup/cpu.pressure → some avg60above 40% for 2 minnever on its own (CPU-bound is slow, not broken)
Memory pressure/sys/fs/cgroup/memory.pressure → full avg10above 5% for 2 min, or memguard grew swapabove 30%: the box is close to not answering
Process killedmemguard reap line—any kill in the last 10 min
SizeSUPERSET_SANDBOX_VCPUS / memory.maxshown in the hover card, and used to label the meters

Thresholds are a starting guess. This box read cpu some avg60 = 21% while only a few agent commands ran, so the "some" line is noisy. Tune the numbers with a real load test before shipping (see open questions).

Plumbing. host-service reads these files every few seconds and adds optional fields to its existing sandbox.status procedure: { cpuPressure, memoryPressure, lastReap }. The desktop polls it only while the workspace is visible or hovered. Old host-services and local hosts return no fields, and the UI shows nothing. That is the compatible pattern from packages/trpc/AGENTS.md.

Rollout. host-service reaches boxes with the nightly sandbox release, and each box picks it up on its next boot or wake. The desktop side ships with the desktop release. No migration, no new environment variables. Reading memguard's kills needs memguard to write a small state file, which is a rootfs/usr/local/bin change, so that release must push a new image. The normal production release does that.

4 · How others do it

Asked: does Claude, or anyone else, show pressure with a way to get more? Partly. Nobody does both well, and that is the gap this fills.

ProductIndicatorWay to get moreWhat we take
Claude Code Context meter in the status line and a usage ring in desktop. Quiet until near the limit, then "Context left until auto-compact: N%". Indirect: /compact, or clear. No "buy more". Quiet until a threshold, then specific. Its most common complaint is that compaction happens silently. We have the same risk with memguard kills, which is why red names what died.
GitHub Codespaces No standing meter. "Change machine type" from the codespace's … menu, a VS Code command, or gh codespace edit --machine. A running codespace stops first. The menu location and the "it restarts" rule match ours. Lacks the signal, so people guess.
Replit Resources panel in the workspace header: RAM, CPU, storage as used vs allocated. Docs point to Boosts when usage stays high. The panel itself has no button. Always-on meters are useful but noisy. We put ours in the hover card instead of the header.
Coder Template-defined agent metadata, often coder stat CPU and memory, shown on the workspace page. Change template parameters and rebuild. Shows the numbers but leaves the meaning to the reader.

5 · Open questions

Should agents see pressure too?

An agent that knows the box is memory-bound could run one test file instead of the suite. host-service could add a line to the agent's context when red. Separate ticket?

Who may resize?

For org-visible workspaces, should only the owner resize, since everyone else using the box loses their running processes too? Check what setMachineSize allows today.

Suggest a size, or just "next size up"?

Next size up is simple and right most of the time. Memory kills could suggest the size whose RAM fits the killed process plus current use.

Smaller sizes

Should the hover card ever suggest going down, for a box that has been quiet for a week? Saves credits, but it is a different feature.

Load test for thresholds

Run the desktop typecheck and the dev stack on a 2/4 and a 4/8 box, record PSI, and set amber and red from that, not from this page's guesses.

Mobile

Mobile already offers restart. Resize and the red banner could follow; the API is the same.
