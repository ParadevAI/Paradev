title: Migrate from Conductor Cloud
description: Move your Conductor Cloud workspaces to Paradev before Conductor Cloud shuts down
---

Conductor is [joining Meta](https://www.conductor.build/announcement), and Conductor Cloud is shutting down. This guide gets your cloud work out of Conductor and into Paradev, either on your Mac or in a Paradev cloud workspace.

<Callout type="warn" title="Conductor Cloud's timeline">
- **November 13, 2026:** Conductor Cloud goes read-only. You can still read chats and export data, but you cannot send messages to agents.
- **November 20, 2026:** Conductor Cloud shuts down and Conductor begins to delete cloud data.

Work that exists only in a Conductor Cloud workspace is not on your machine. Move every workspace you want to keep before November 20.
</Callout>

For the local Conductor app, see [Migrate from Conductor](/migrate-from-conductor).

## What Maps to What

| Conductor Cloud | Paradev |
|---|---|
| Cloud workspace | [Cloud workspace](/cloud-workspaces) |
| Cloud setup: repositories, variables, secrets | [Environment](/cloud-workspaces#1-create-an-environment) with [variables](/cloud-workspaces#2-add-variables) |
| Setup script and actions | `.paradev/config.json` ([lifecycle scripts](/setup-teardown-scripts)) |
| Routines | [Automations](/automations) with **Cloud** as the device |
| iOS app | [iPhone and iPad app](/mobile) |
| Cloud organization | Paradev organization. Environments are visible to the whole organization by default |

## 1. Save Your Work in Conductor

Do this first, before November 13 if you can.

1. **Push every branch.** In each Conductor Cloud workspace, commit all changes, including new files (`git add -A`), and push the branch. A pushed branch is safe on GitHub whatever you choose next.
   A push does not include Git-ignored files, such as `.env` files or local data. Copy out any you need before November 20.
2. **Export your data.** In Conductor, go to **Settings → Account → Export data**. This keeps a copy of your chats. Paradev cannot import Conductor chats, so this export is your record of them.

Then pick where to continue: on your Mac, or in a Paradev cloud workspace.

## 2a. Continue on Your Mac

1. In Conductor, right-click the cloud workspace and choose **Transfer to local**. Conductor moves the workspace and its chats to your Mac.
2. Follow [Migrate from Conductor](/migrate-from-conductor) to import the workspace into Paradev and convert your scripts.

Conductor can attach a cloud workspace on your Mac to its own copy of the repository under `~/conductor/`, not to your clone. Then the workspace does not appear in your project's import list. To check, run this in the workspace folder:

```bash
git rev-parse --path-format=absolute --git-common-dir
```

If the path is under `~/conductor/`, commit and push the branch from that folder. Then create a workspace from the **Existing branch** in your own clone.

If you only pushed the branch, add the repository in Paradev and create a workspace from the **Existing branch** instead. See [Workspaces](/workspaces).

## 2b. Continue in a Paradev Cloud Workspace

Paradev cloud workspaces keep agents working when your laptop is closed, and you can open them from desktop, iPhone, or iPad. They need a paid plan, and the GitHub repository must be shared with the Paradev GitHub App. See [Requirements](/cloud-workspaces#requirements).

<Callout type="info">
Cloud workspaces are in early access. If you do not see **Cloud** in the device picker yet, continue on your Mac (2a) for now.
</Callout>

### Add your setup scripts

Cloud workspaces run the setup scripts in `.paradev/config.json` from the repository. Convert your Conductor setup script as described in [Convert Your Scripts](/migrate-from-conductor#3-convert-your-scripts), then commit and push the file to every branch you will use as a base branch. A cloud workspace started from a branch without it does not run your setup.

`CONDUCTOR_PORT` is not set in Conductor Cloud, so cloud scripts usually do not need a port change.

### Create an environment

1. Open **Settings → Environments** and click **New environment**.
2. Add the repositories your Conductor Cloud workspaces used. The first one is the primary.
3. Click the environment and add the variables and secrets your Conductor Cloud setup used.

Do not add agent API keys or GitHub tokens. Cloud workspaces ignore them: agents use your sign-in from **Settings → Agents**, and GitHub access comes from your connected GitHub account. See [Credentials](/cloud-workspaces#credentials).

Not sure what the project needs? Click **Set up with an agent** in **Settings → Environments**. Claude installs what the project needs and writes its `.paradev/config.json`.

### Continue each branch

1. Press **⌘N** and pick **Cloud** in the device picker.
2. Pick the project and the environment.
3. Choose the branch you pushed from Conductor as the base branch. Paradev creates a new working branch from it, so an open pull request for the Conductor branch does not get the new commits. Open a new pull request from the new branch, or merge it into the old one.
4. Tell the agent where to pick up, for example "Continue the work on this branch. Read the last commits and the open PR first."

From the CLI:

```bash
superset workspaces create --base-branch <pushed-branch> --agent claude \
  --prompt "Continue the work on this branch"
```

If more than one environment has repositories, also pass `--environment <id>`. Run the command without it to see each environment's ID.

When one workspace is fully set up, right-click it and choose **Save as environment**. New workspaces then start from that snapshot instead of running setup each time. See [Save a set-up workspace](/cloud-workspaces#4-save-a-set-up-workspace-as-an-environment).

### Move your routines

Recreate each Conductor routine as a Paradev [automation](/automations). Pick **Cloud** as the device to run each session in a new cloud workspace, and pick the [machine size](/cloud-workspaces#machine-sizes). Automations can run on a schedule or when something happens in GitHub, Slack, Linear, Sentry, and other tools.

## 3. Check Your Usage

Paradev meters cloud usage in GB-hours: machine memory multiplied by run time. A stopped or sleeping workspace uses none, and a workspace stops by itself after about an hour of no activity. **Settings → Billing** shows what you have used. See [Usage and Billing](/cloud-workspaces#usage-and-billing).
