<Callout type="info">
The Chat UI is coming soon. It is not yet available to everyone, so you might not see it in the app yet.
</Callout>

The Chat UI shows an agent session as a chat instead of a terminal. You see the agent's messages, tool calls, and file edits as a readable transcript, and you approve or decline actions with a click instead of a keypress.

It is not a separate agent. Paradev runs the agent CLI you already installed, over the [Agent Client Protocol](https://agentclientprotocol.com), so a chat uses the same login, settings, and MCP servers as that CLI in a terminal. A session can move between the chat and the terminal without starting over.

## Open a Chat

- **New workspace:** pick a supported agent when you create a workspace, and its session opens as a chat.
- **Existing agent terminal:** use the **CLI** / **Chat** toggle in the agent pane's header. Switching resumes the same session, so the agent keeps its context. Switch back to **CLI** at any time.

The toggle appears for a running session of a supported agent.

## Supported Agents

| Agent | Chat UI | Minimum CLI version |
|:------|:-------:|:--------------------|
| Claude Code | ✅ | 2.1.226 |
| Codex | ✅ | 0.160.0 |
| OpenCode | ✅ | 1.15.5 |
| Pi | ✅ | Any |
| Other agents | — | — |

If your CLI is older than the minimum, the chat does not start and Paradev tells you which version it needs. Agents without chat support still run in a Paradev terminal.

## Update the agent CLI

When a newer Claude Code or Codex release is out, a notice above the chat's message box says so. **Update** opens a terminal under the chat and runs the update there, so you can watch it. When it finishes, **Restart** loads the new version into the chat and keeps the conversation. Dismiss the notice to hide it until the next release.

If Claude Code or Codex is older than the minimum, the chat offers the same **Update** in place of the conversation and resumes on its own once that update is installed. When Paradev can't tell how the CLI was installed, it shows **How to update** instead. Other agents show which version they need.

The update command depends on how the CLI was installed, and Paradev reads that from where the binary lives:

| Installed with | Update command |
|:---------------|:---------------|
| Claude Code's native installer (`~/.local/bin/claude`) | `claude update` |
| Homebrew | `brew upgrade --cask claude-code` (or `claude-code@latest`, `codex`) |
| npm | `npm install -g --prefix <prefix> <package>@latest`, into the prefix that holds the CLI, with `sudo` when you can't write to that prefix |
| bun | `bun add -g <package>@latest` |
| pnpm | `pnpm add -g <package>@latest` |

Paradev never runs one package manager over another's install. If it cannot tell how the CLI was installed, it shows **How to update**, which links here; update the CLI with the tool you installed it with.

In a cloud workspace, the agent CLIs come with the workspace image and change only when the image does. The chat shows no update notice there, and a CLI below the minimum shows **How to update**, since only a new image can fix it.
