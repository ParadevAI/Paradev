Paradev and Background Agents both run coding agents while you do other work, and both are MIT-licensed. They are built for different jobs. Background Agents, which its README calls **Open-Inspect**, is an open source system inspired by Ramp's internal Inspect agent. Your company deploys it on Cloudflare plus a sandbox provider such as Modal, and every session runs in a cloud sandbox that people start from the web, Slack, GitHub, Linear, webhooks, or a schedule. Paradev is a workspace for the agent CLIs you already use, such as Claude Code and Codex. Each task gets its own Git worktree and terminal, on your Mac, on hosts you add, on your own Linux server, or in a Paradev cloud workspace (beta). Choose Open-Inspect when a platform team wants to run an internal background agent for the whole company. Choose Paradev when developers want to run, watch, and review their own agents without operating that system.

## What Is Background Agents (Open-Inspect)?

The project site calls it "an open framework for background coding agents." The README title is "Background Agents: Open-Inspect," and it says the design follows [Ramp's Inspect](https://builders.ramp.com/post/why-we-built-our-background-agent), an agent Ramp built for internal use.

The control plane runs on Cloudflare Workers and Durable Objects, with one Durable Object per session. Each session runs in a sandbox with Node.js, Python, Bun, git, the GitHub CLI, and a headless browser for screenshots. A sandbox can also give you a browser-based VS Code, a web terminal, and up to 10 tunneled dev server ports. Filesystem snapshots, prebuilt images, and warming as you type make sessions start fast. One session can work across up to 10 repositories and open a PR in each. Agents can split work into child sessions, each in its own sandbox. Managed Skills give agents shared instructions at session start.

People reach the agent from many places. The Slack bot starts a session from a mention or DM. The GitHub bot reviews PRs when they open or when someone mentions it. The Linear bot starts a session from an issue and links the PR. Automations run on cron, on Sentry alerts, on GitHub workflow runs, or on webhooks, and pause after 3 failures in a row.

The README is clear about scope: the system is for **single-tenant deployment only**, where every user is a trusted member of the same organization. It recommends deploying behind your company's SSO or VPN and installing the GitHub App only on the repos you intend.

## What Is Paradev?

Paradev is a workspace for the coding agents you already use. It runs each agent CLI in its own Git worktree and persistent terminal, with presets for Claude Code, Codex, Cursor Agent, OpenCode, Gemini CLI, GitHub Copilot CLI, Grok, Kimi Code, Mistral Vibe, Amp, and Pi, plus custom commands. The Changes pane shows the diff and lets you commit, push, and open a pull request. The Pull Requests view shows CI checks and line comments you can send to an agent. An in-app browser with port detection and Design Mode, Automations, Tasks synced with Linear and GitHub Issues, a Slack bot, a CLI, a TypeScript SDK, and an MCP server sit around that. A [chat interface](https://docs.paradev.com/chat) shows a Claude Code, Codex, OpenCode, or Pi session as a chat, and a CLI / Chat toggle switches the same session back to the terminal. Paradev is open source under the MIT License.

## Key Differences

### A system you operate vs an app you install

Open-Inspect is infrastructure. The Getting Started guide has you create accounts with Cloudflare, a web host (Vercel or Cloudflare Workers), and a sandbox provider (Modal by default), make a GitHub App, and fill in one `terraform.tfvars` file. Terraform then builds the Workers, Durable Objects, D1 database, and sandbox setup. An AWS production path also exists. Someone on your team owns upgrades, access settings, and secrets after that.

Paradev is a desktop app you install. Workspaces run on your Mac by default. For work away from your desk, you add a host with Remote Access, run the Paradev host on your own Linux server with [Bring Your Own Cloud](https://docs.paradev.com/bring-your-own-cloud), or use [cloud workspaces](/cloud) (beta), which Paradev hosts. A BYOC server keeps repos and agent sign-ins on that server and needs no inbound ports.

### Where the sandbox lives

In Open-Inspect, every session is a fresh cloud sandbox on the provider you choose, with snapshots saved after each prompt. That gives each task a clean, isolated machine and lets many tasks run at once without touching a laptop.

In Paradev, isolation is a Git worktree and branch on the host. A worktree separates files, not processes, so tasks on one host share that machine. Cloud workspaces (beta) give you a hosted machine per workspace, started from an environment with 1 to 20 GitHub repos, variables, secrets, a region, and a machine size. You can save a set-up workspace as an environment snapshot.

### Agents and models

Open-Inspect runs one of two harnesses inside the sandbox: OpenCode or the Claude Agent SDK. It lets you pick the model per session and use ChatGPT, Claude, or SuperGrok subscriptions as well as API keys.

Paradev runs the full agent CLIs, with their own logins, settings, and MCP servers. You can switch agents between tasks, or continue a session with another agent. Claude Code and Codex have a structured handoff. Paradev never proxies model calls.

### Hands-off intake vs hands-on sessions

Open-Inspect is built to be asked from where the team already works, then left alone. A Slack message, a Linear issue, a Sentry alert, or a cron job starts a session, and results thread back with a PR. Several people can join one session, and each person's prompts are attributed in the commits.

Paradev also has intake: Automations run on a schedule or on GitHub, Slack, Linear, and other events, Tasks sync with Linear and GitHub Issues, and the Slack bot starts workspaces from a mention. Its center, though, is the developer's own session. You watch the terminal, answer prompts, run your own commands, review the live diff, and open the PR in the same window. The iPhone and iPad app lets you check in from your phone.

### Security model

Open-Inspect's README says to treat it as a trusted internal tool. All users share one GitHub App installation. Sandbox credentials are limited to the session's repos, but they are cached on disk, so snapshots can keep them, and removing a grant does not revoke a token that was already issued. Team read isolation depends on a setting that defaults to `shadow`.

Paradev agents run on hosts you choose with your own agent sign-ins. Organizations grant host access per member, and Enterprise adds SAML SSO, SCIM, audit logs, and SOC 2 Type II.

## Which Should You Choose?

**Choose Background Agents (Open-Inspect) if you:**

- Have a platform team that wants to run an internal background agent for the whole company.
- Want every task in a fresh cloud sandbox on Modal, Daytona, Vercel Sandbox, E2B, or Boat.
- Want people to start agents from Slack, Linear, GitHub, Sentry alerts, and webhooks, and get a PR back.
- Want multiplayer sessions and per-prompt commit attribution.

**Choose Paradev if you:**

- Want to run Claude Code, Codex, or another CLI agent yourself, without operating infrastructure.
- Want to choose per task between your Mac, your own hosts, your own Linux server, and cloud workspaces (beta).
- Want a live terminal, diff, commits, and pull request review next to the agent.
- Want an iPhone and iPad app, Enterprise SSO and SCIM, or a team that is not one trusted tenant.

## Verdict

Open-Inspect is a solid open source base for a company that wants its own Ramp-style background agent and has the people to run it. Paradev is for developers and teams who want to run the agents they already use, see each session, and review the work, with cloud options that do not need a Terraform deploy. The two can sit side by side: a background system for fire-and-forget tasks, and Paradev for the work you want to steer.

## Frequently Asked Questions

### What is Open-Inspect?

Open-Inspect is the name the Background Agents README uses for the project. It is an open source background coding agent system inspired by Ramp's Inspect, under the MIT License.

### Is there a hosted version of Open-Inspect?

The project describes itself as open source and self-hostable and does not list a hosted plan or pricing. You deploy it with Terraform on your own accounts.

### Can Paradev run agents in the background?

Yes. Workspaces on a Remote Access host, a [Bring Your Own Cloud](https://docs.paradev.com/bring-your-own-cloud) server, or a [cloud workspace](/cloud) (beta) keep running when your laptop is closed. Automations start agents on a schedule or on GitHub, Slack, Linear, and other events.

### Which agents does Open-Inspect support?

It runs OpenCode or the Claude Agent SDK as the harness, with Anthropic and OpenAI models by default and other providers opt-in. Paradev runs the agent CLIs themselves, including Claude Code, Codex, and OpenCode.

### Are both open source?

Yes. Both projects use the MIT License.
