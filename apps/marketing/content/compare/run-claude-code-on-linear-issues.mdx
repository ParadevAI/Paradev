To run Claude Code in parallel on Linear issues, give each issue its own Git branch and its own agent session, start them together, and let the issue keep the status and the owner. In [Paradev](https://paradev.com), open **Tasks**, switch the source to **Linear**, select the issues, and click **Run in workspace**. Paradev creates one workspace per issue on Linear's branch name, starts Claude Code (or Codex, or another CLI agent) with the issue as its prompt, and moves each issue to In Progress. Each teammate runs this on their own machine or a shared host, with their own Claude or OpenAI subscription.

The main alternatives are Linear's own agent integrations (assign an issue to Codex or Cursor, which run in the vendor's cloud) and open-source bridges such as Cyrus, which runs Claude Code against issues assigned to it. The choice comes down to where the agent should run and who reviews the result.

This guide is written for a team of two to ten engineers who already track work in Linear. It is published by Paradev. Details about other tools come from their own docs as of October 2026.

## What does a small team need from a Linear-to-agent setup?

Four things, whatever tool you pick:

1. **One branch per issue.** Linear's branch name (for example `eng-142-fix-export-timeout`) links the branch and the pull request back to the issue automatically.
2. **One agent session per issue**, so a conversation about issue 142 does not leak into issue 143.
3. **Status that moves without someone dragging cards.** At minimum, In Progress when an agent starts and In Review when a pull request opens.
4. **A named human reviewer.** An agent can write the change. A person on the team still owns the merge.

Git worktrees cover the first two on one machine: each issue gets its own directory and branch. They do not stop two issues from touching the same files. If issue 142 and issue 143 both edit `export.ts`, the second pull request to merge has a conflict to resolve, the same as with two people. Split issues by area before you hand them out.

## How do I run several Linear issues at once in Paradev?

Connect Linear once under **Integrations** (Pro plan). Then, from the desktop app:

1. Open **Tasks** in the sidebar and set the source toggle to **Linear**. Filter by project, status, or assignee, for example your cycle's unstarted issues assigned to you.
2. Check the issues you want to hand off. Keep it to issues that are small and clearly described.
3. Click **Run in workspace**, pick the project (the repository) and the agent, such as Claude Code.
4. Leave **Auto-run command** on to start every agent now, or turn it off to stage each command and read the prompt first.

Paradev creates one workspace per issue. Each is a Git worktree on Linear's branch name, with the agent already working and the issue text as its prompt. To change how an issue becomes a prompt, for example to add "write a test first" or "stop and ask if the issue is unclear", edit the **Task Prompt Template** for that agent under **Settings → Agents**.

The sidebar then shows one row per issue with the agent's state: working, waiting for input, or ready for review. Open a row to read the terminal, answer the agent, or review the diff in the **Changes** pane. When you are satisfied, commit, push, and open the pull request from the same pane.

## Can I do it from the CLI or from Linear itself?

Yes, both.

From the CLI, list your Linear issues and create a workspace for one:

```bash
superset tasks list --tracker linear --assignee-me
superset workspaces create --local --project <project-id> \
  --name eng-142 --task <task-id> \
  --agent claude --prompt "Fix the export timeout described in the linked issue"
```

When `--branch` is omitted, `--task` uses the issue's Linear branch name as is. Use `--agent codex` for Codex. Run the command once per issue in a loop to fan out a batch.

From Linear, use its **custom coding tool** setting. A short wrapper script lets **Work on issue → Custom script** call `superset workspaces create` with the issue's branch and prompt, then `superset workspaces open` to show it in the desktop app. The [Linear integration docs](https://docs.paradev.com/use-with-linear) have the full script and the `~/.linear/coding-tools.json` file.

## Can an agent start when an issue is assigned or labeled?

Yes, with an [Automation](https://docs.paradev.com/automations) (Pro). Add a Linear trigger for an issue that is created, moves to a status, or is assigned, and scope it by team, project, label, status, or assignee. A common pattern reads "Issue moved to **Todo** in **Engineering** with label **agent**": when an issue with the `agent` label moves into Todo, the automation creates a workspace for it on the device you picked and starts the agent with your prompt plus the issue in front of it. Adding the label alone does not fire the trigger, so add it before the issue moves.

```text
A Linear issue is in the event above. Read it and the code it mentions.
If the issue is unclear, stop and write your questions to QUESTIONS.md.
Otherwise make the change, add or update tests, run the test suite, and
open a draft pull request with `gh pr create --draft` that links the issue.
```

Two limits to plan for: the target device has to be online when the event arrives, or the run is recorded as missed and is not retried. Delivery is at least once, so keep the prompt safe to run twice.

## How does the team keep track of who reviews what?

Keep ownership in Linear and review in GitHub, and let Paradev connect them:

- **Linear** keeps the assignee and status. With the integration connected, starting a workspace from an issue moves it to In Progress, and the branch name links the pull request back to the issue.
- **Paradev's Pull requests view** filters by *Awaiting review from you*, *Changes requested*, and *Approved review*, with each PR's checks next to its diff. Merging, closing, and commenting act on the real PR with your GitHub permissions.
- **Workspaces** filter by who created them, so you can see a teammate's agent runs without mixing them with yours.

To give the agent itself tools to read and update Linear, such as posting a summary comment on the issue, install the [Linear plugin](https://docs.paradev.com/plugins/available/linear).

## What do other tools do for the same job?

| Option | Where the agent runs | Agents | Good fit |
| --- | --- | --- | --- |
| Paradev Tasks and automations | Your machines or a shared host | Claude Code, Codex, and other CLI agents | Teams that want agents on their own machines and subscriptions, with diffs reviewed before the PR |
| Codex in Linear | OpenAI's cloud | Codex | Assign or mention @Codex on an issue, and it posts progress back |
| Cursor in Linear | Cursor's cloud agents | Cursor's agent | Teams already on Cursor; assign an issue to Cursor or mention @Cursor |
| Linear coding sessions | Configured in Linear | Claude Code and Codex, per Linear's coding sessions page | Teams that want everything to stay inside Linear |
| Cyrus | A machine you run | Claude Code | Open-source bridge that runs Claude Code on assigned issues |

Linear's native agents need the least setup and keep the conversation on the issue. The tradeoff is that the work runs in the vendor's environment, which may not have your local services, seeded database, or VPN. Paradev runs the agent CLIs you already use on machines you control, so the agent sees what your developers see, and a person reviews the diff in the app before the pull request goes up. You can use both: assign the quick, self-contained issues to a cloud agent and run the ones that need local context in Paradev.

## Frequently Asked Questions

### Does Claude Code integrate with Linear?

Not on its own. Claude Code reads Linear through an MCP server or a plugin. To start Claude Code from Linear issues, use a tool that bridges the two: Paradev's Tasks view and Linear triggers, Linear's coding sessions, or Cyrus.

### Can several Claude Code agents work on different Linear issues at the same time?

Yes. Give each issue its own worktree and branch so the agents do not edit each other's files. In Paradev, selecting several issues and clicking **Run in workspace** does this in one step. Issues that touch the same code can still conflict at merge time.

### Do I need a Paradev seat for each teammate?

Each person who uses Paradev needs their own account. The Linear integration, automations, and remote hosts are on the Pro plan. See [pricing](/pricing).

### Does Paradev move Linear issues to In Progress?

Yes, when the Linear integration is connected and you start a workspace from an issue. Moving the issue to In Review or Done follows Linear's own GitHub integration when the pull request opens or merges.

### Can I use Codex instead of Claude Code?

Yes. Pick Codex in **Run in workspace**, or pass `--agent codex` to the CLI or the automation. Different issues in the same batch can use different agents.
