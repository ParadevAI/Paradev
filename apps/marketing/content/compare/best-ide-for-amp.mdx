Amp is a multi-model coding agent that picks models for you by mode. It runs in a terminal UI, on the web, in macOS, iOS, and Android apps, and on "orbs," cloud machines that keep working after you close your laptop. Since October 2026 you can also run orbs on your own infrastructure. So the best "IDE for Amp" depends on where you want the work to happen and whether you want several tasks, or several agents, at once.

Facts were checked against Amp's own manual, pricing, and news pages on November 5, 2026.

## The Short Version

| Where you run Amp | Best for | Parallel tasks on one repo? | Main tradeoff |
|---|---|---|---|
| **Paradev** | Many Amp tasks at once, next to other agents | Git worktrees for local branch-based workspaces | Not a single-file editor experience |
| **Amp terminal UI** | One focused task | Subagents inside a thread | You manage separate tasks yourself |

## The Options

### Amp terminal UI

The `amp` terminal UI is the core of Amp. You pick a mode on a dial from low to ultra, subagents run automatically, you can add custom agents through plugins, and `-x` runs Amp headless for scripts. It supports MCP, plugins, skills, and toolboxes. Its home page lists installs for macOS, Linux, WSL, and Windows. For one task at a time, start here.

### Orbs

Orbs are cloud machines, one per thread, that keep working after you close your laptop. Run a task in an orb with `-ox`. Orbs can also start from a Slack mention, a Linear issue you assign to Amp, a new GitHub or GitLab issue or pull request, a webhook, or a schedule, and an orb can start a cloud Mac to build and test iOS and Mac apps. The Individual plan starts at $20 a month with 45,000 orb minutes; on the free plan, Amp-hosted orbs are pay-as-you-go.

### Self-hosted orbs

Since October 22, 2026, you can run orbs on your own infrastructure. You run `amp orb provider` with a dispatch program for a platform such as Docker, Kubernetes, E2B, Modal, or Daytona, and Amp turns that compute into orbs. Self-hosted orbs are free for individuals and teams, and since October 28 you can add a personal provider without a workspace admin. Amp's own post says "you probably shouldn't self-host orbs," and it aims the feature at enterprises with rules about where code runs.

### Runners

Runners execute Amp threads on machines you choose. Since September 22, 2026, a runner creates Git worktrees for its threads, so several threads can work one repository at once. Runners can be shared across a team, and the Amp Mac app can act as one. Since October 16, you can see and control a macOS or Linux runner's desktop.

### Amp web, macOS, iOS, and Android apps

Amp's threads follow you across the web and its macOS, iPhone, iPad, and Android apps, so you can start a task at your desk and check on it from your phone. The Android app arrived on October 27, 2026.

### Paradev

Paradev runs Amp as a built-in agent. Each new local branch-based workspace gets its own Git worktree and terminal, so several Amp tasks can run on the same repository at once. Workspaces run locally, on your own remote hosts through Remote Access, on a Linux server in your own cloud account ([Bring Your Own Cloud](https://docs.paradev.com/bring-your-own-cloud)), or in [cloud workspaces](/cloud) (beta), included with Team and Ultra. You can also run Claude Code, Codex, or any other CLI agent in the next workspace and compare the results. Around it you get a Changes pane that commits, pushes, and opens PRs, a Pull Requests view with CI checks, an in-app browser, automations on schedules and GitHub, Slack, and Linear events, a [chat interface](https://docs.paradev.com/chat) for Claude Code, Codex, OpenCode, and Pi, and an iPhone and iPad app. Paradev is open source under the MIT License and never proxies model calls. Worktrees separate working files but do not sandbox processes or prevent merge conflicts; see [workspace types](https://docs.paradev.com/workspaces).

For the direct comparison, see [Paradev vs Amp](/compare/superset-vs-amp).

## How To Choose

- For one task, use the Amp terminal UI.
- For work that keeps going without your machine, use orbs.
- For orbs that must run on your own infrastructure, use self-hosted orbs.
- For your own machines shared across a team, use runners.
- For many Amp tasks next to other agents, with PRs and review in one place, use Paradev.

## Verdict

Amp's own surfaces are the best place for Amp alone, and orbs, hosted by Amp or by you, are its answer to work that runs while you are away. Once you want Amp next to Claude Code, Codex, or other agents on the same repository, with review through to the pull request, run it in a workspace like Paradev.

## Frequently Asked Questions

### What is the best IDE for Amp?

For one task, Amp's terminal UI. For work that runs without your laptop, orbs. For several Amp tasks next to other agents on one repository, a worktree workspace like Paradev.

### Does Amp work in VS Code?

Amp says it no longer maintains editor extensions. Its current surfaces are its terminal UI, web, and macOS, iOS, and Android apps. Run the terminal UI in any editor's terminal, or in Paradev.

### How do I run Amp and Claude Code together?

Give each its own Git worktree. In Paradev, each runs in its own workspace on the same repository. Since October 10, 2026, Amp's Claude Code mode can also use your Claude subscription.
