What happens behind the Claude modal

#WhoWhat
1Modal → APIagentCredential.claudeOauthStart: makes code_verifier + state, stores them for 10 min against the person, returns the authorize URL.
2Person ↔ claude.aiSigns in, clicks Authorize. Anthropic's callback page shows the code.
3Modal → APIagentCredential.claudeOauthFinish({ code }): checks state, exchanges code + verifier for the token, deletes the verifier.
4APIChecks the token, saves it encrypted as kind subscription, the same row Settings writes today. The token never goes back to the client.
5API → boxesApplies the firewall rules to the person's running boxes now, not at the next keepalive.
6Modal → chatRestarts the agent and continues the turn.

The new procedures are additive, so released clients are not affected. Settings › Agents gets the same “Open claude.ai” button instead of “run claude setup-token in a terminal”.

What does not change

  • Manual mode, for people who rotate several accounts: the card stays “The agent is signed out” with Continue and Agent settings. The modal never replaces a Manual setting.
  • Someone else's box: no modal. The card says the workspace creator has to sign in.
  • Local workspaces: the agent uses your own login there, so the card keeps the login command and adds “Run in terminal”.

Risks to clear before building

Anthropic's terms for running Claude's OAuth from our server.The flow uses Claude Code's public OAuth client. The token is only ever used by Claude Code running in the box, and we already do the same for Codex with OpenAI's client. Still, Anthropic restricts third-party use of subscription sign-ins. Someone should confirm this is allowed for us before it ships. If it is not, the fallback is the paste-a-key screen only.
Endpoints and scopes are not documented.The authorize/token URLs, the scope for a long-lived token, and the code format (code#state) come from what the Claude Code CLI does. I'll check them against the current CLI and keep them in one module, as chatgpt.ts does, so a change breaks one place.
Applying a new credential to running boxes at once.Today a saved credential seems to reach a box at its next wake or keepalive. To verify, and add if missing.
