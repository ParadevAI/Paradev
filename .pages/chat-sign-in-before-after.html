Why the full restart is not needed

Part of a sign-inWhere it livesCan it change on a running box?
The real tokenSandbox firewall rule (swaps the placeholder on the way out)Yes. applySandboxPolicy already updates a running box. It is how the hourly GitHub token stays fresh.
Placeholder variables (CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_API_KEY, …)host-service memoryYes. sandbox.setEnvironment replaces them live, and new agents and terminals pick them up.
Codex login file~/.codex/auth.jsonYes. writeSignInFiles already runs on every wake, including a box that is running.
An agent process that is already runningIts own environment, fixed at startNo. Restart that process only. The chat already has “restart the agent and continue”.

A wake already does the first three things. The banner exists only because of the last row, and a workspace restart is a much bigger tool than that row needs. So after a save we run those three steps on the person's running boxes, mark them current, and restart only the agent that failed.

If you only replace a token of the same kind (a token for a token, or a key for a key), the variable names stay the same. Then only the firewall changes, and the agent may not need a restart at all. We restart it anyway: it is cheap and always correct.

What stays out of scope

  • Agents started from a terminal (not chat) keep their old environment until you start them again. The modal says “Agents started from a terminal pick this up the next time they start.”
  • Someone else's box runs on its creator's sign-in: no modal there.
  • Manual mode is unchanged.
